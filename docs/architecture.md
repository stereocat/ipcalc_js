# アーキテクチャ

## 1. アプリケーション概要

`ipcalc_js`は、ブラウザ上で動作するIPv4サブネット計算機です。ユーザーがIPv4アドレスと、任意のプレフィックス長またはドット区切りのサブネットマスクを入力すると、アプリケーションは値を検証して`Netmask`オブジェクトを生成し、次の情報を表示します。

- ドット区切り10進数、2進数、8進数、10進整数、16進数でのアドレス表記
- サブネット長、サブネットマスク、ホストマスク、ネットワーク、ホスト範囲、ブロードキャスト
- 前、現在、次のCIDRブロック
- 静的な特殊用途IPv4アドレス一覧との一致
- 親ブロックと子サブネットの操作可能な階層図

すべての計算はブラウザ内で実行されます。HTTP API、認証、データベース、ユーザー状態の永続化はありません。

## 2. 実行構成

### 開発環境

```text
ブラウザ
  -> Vue CLI開発サーバー（`npm run serve`）
     -> public/index.html
     -> src/main.js
     -> Vueコンポーネントアプリケーション
```

Vue CLIがバンドル、ホットリロード、Babel変換、アセット配信を行います。

### 本番環境

```text
`npm run build`
  -> dist/を生成

ブラウザ
  -> Expressサーバー（`npm start`）
     -> dist/の静的ファイル
     -> クライアント側Vueアプリケーション
```

`server.js`は`process.env.PORT`、未指定の場合はポート3000で待ち受けます。業務用エンドポイントやサーバーサイドレンダリングは提供しません。

## 3. 起動処理とコンポーネント構成

`public/index.html`が`<div id="app">`というマウント先を提供します。その後、`src/main.js`が次の処理を行います。

1. `App.vue`からVue 3アプリケーションを生成する。
2. Element Plusの入力欄と折りたたみコンポーネントを登録する。
3. Vuexストアを登録する。
4. アプリケーションを`#app`にマウントする。

`App.vue`は、ヘッダー、入力領域、初期状態ですべて展開された3つの結果セクションからアプリケーションを構成します。

```text
App
├── AppHeader
├── AppInput
└── Element Plusの折りたたみ領域
    ├── IPAddressTable
    ├── NetmaskTable
    │   └── AppIPBlockAnchor
    ├── SpecialAddressContainer
    │   └── SpecialAddressList
    │       ├── AppIPBlockAnchor
    │       └── AppRFCAnchor
    └── IPBlockTree
```

画面が1つだけのため、Vue Routerは使用していません。

## 4. 状態モデルとデータフロー

Vuexストアは、それぞれ独立した表示コンポーネント間を接続する統合点です。

```text
テキスト入力 / CIDRリンク / ツリーノード
              |
              v
      Vuex mutation
      - setIPAddrString
      - setIPBlock
              |
              v
      共有される選択中ネットワーク
      - ipAddrString: string
      - ipBlock: Netmask
              |
      +-------+---------------+----------------+-------------+
      |                       |                |             |
      v                       v                v             v
IPAddressTable          NetmaskTable   SpecialAddress   IPBlockTree
                                       Container
```

初期状態は`127.0.0.1`と、それを含む`127.0.0.0/8`ブロックです。2つの状態フィールドは、互いに関連していますが異なる概念を表します。

- `ipAddrString`は、表記変換に使用する選択中のホストアドレスを保持します。
- `ipBlock`は、正規化された所属ネットワークを表し、`netmask`ライブラリを介してサブネットの各種プロパティを提供します。

両方の値を必ずまとめて更新してください。一方だけを更新すると、アドレス表記、サブネット表、入力欄、ツリーの内容が食い違う可能性があります。

ストアにはサードパーティー製クラスのインスタンスが含まれています。そのため、状態は単純なJSONではなく、永続化、シリアライズ、タイムトラベル、サーバーハイドレーションにそのまま使用できるとは限りません。

## 5. 入力処理

`AppInput.vue`は、キー入力のたびに値をコミットせず、編集中の入力をローカルに保持します。処理の流れは次のとおりです。

```text
keyup
  -> 正規表現でIPv4部分を検証
  -> 任意のプレフィックス長またはドット区切りマスクを検証
  -> `new Netmask(input)`を生成
  -> 失敗時は警告を表示して処理を停止
  -> 有効な入力後1000ミリ秒待機
  -> アドレスとNetmaskオブジェクトをVuexへコミット
```

次の形式を受け付けます。

```text
192.0.2.1
192.0.2.1/24
192.0.2.1/255.255.255.0
```

このコンポーネントはストアの変更を監視するため、別の場所から開始された移動もテキスト入力欄へ反映されます。また、直近のマスクがプレフィックス長とドット区切りマスクのどちらで表現されたかを保持します。

## 6. 計算処理の責務

### `IPAddressTable.vue`

`ip.toLong()`とJavaScript標準の基数変換を使用し、ホストアドレスを複数の数値表記で表示します。依存する状態は`ipAddrString`だけです。

### `NetmaskTable.vue`

現在の`Netmask`インスタンスが提供する次のプロパティを読み取ります。

- `bitmask`、`mask`、`hostmask`
- `base`、`first`、`last`、`broadcast`
- `size`
- 隣接ブロックを求める`next(offset)`

また、ドット区切りの2進数表現を生成し、現在のプレフィックス長に従ってネットワーク部とホスト部を視覚的に分離します。

### 特殊用途アドレス関連コンポーネント

`special-addr-info-defs.js`は、CIDR、説明、RFC番号、任意の廃止済みRFC番号を含む静的配列です。`SpecialAddressContainer.vue`は、次の2種類の検索を行います。

- 選択中のブロックに含まれる特殊用途ブロック
- 選択中のブロックを含む特殊用途ブロック

`SpecialAddressList.vue`が結果を表示し、`AppRFCAnchor.vue`と`AppIPBlockAnchor.vue`が、それぞれ外部RFCへの移動とアプリケーション内のCIDR移動を提供します。

### `IPBlockTree.vue`

ツリーコンポーネントは、設定された深さに達するか`/32`の葉に到達するまで、CIDRを同じ大きさの2つの子サブネットへ再帰的に分割します。そのオブジェクトツリーをD3階層へ変換し、partitionレイアウトを適用します。

D3はSVGの矩形とテキストを命令的に生成・更新します。Vueがコンポーネントのライフサイクルと共有状態を所有し、D3がSVGノードを所有します。ストアのwatcherは、選択変更後にレイアウトを再描画します。矩形またはラベルをクリックすると、新しい`Netmask`が生成され、ストアへコミットされます。

## 7. スタイルとUI依存関係

- Element Plusがメインの入力欄と折りたたみ表示を提供します。
- `src/css/info-table.css`が2つのデータ表をスタイリングします。
- `src/css/addr-tree.css`がD3の矩形、ラベル、選択対象、ホバー状態をスタイリングします。
- コンポーネント固有のスタイルは、各Vue単一ファイルコンポーネント内に置かれています。

Element Plusのスタイルは、`babel.config.js`で設定されたBabel importプラグインを通して読み込まれます。`src/plugins/element.js`は現在使われていないため、アプリケーション起動処理に関与するものとして扱わないでください。

## 8. 依存関係の役割

| 依存関係 | アーキテクチャ上の役割 |
| --- | --- |
| Vue 3 | コンポーネント実行環境とリアクティブな描画 |
| Vuex 4 | 選択中アドレスの共有状態管理 |
| Element Plus | 入力欄と折りたたみ表示 |
| `netmask` | IPv4サブネットモデルと派生サブネット情報 |

| D3モジュール | 階層レイアウト、SVG選択、トランジション、イージング |
| Express | 本番用静的アセットの配信のみ |
| Vue CLI/Babel | 開発サーバーと本番バンドル |
| ESLint | 静的ソースチェック |

## 9. テストと品質の現状

現在、このリポジトリには自動テストスイートがありません。ユニットテスト、コンポーネントテスト、E2Eテストのファイル、テストランナーの依存関係、`npm test`スクリプトはいずれも存在しません。`npm run lint`と`npm run build`はチェックであり、振る舞いを検証するテストではありません。

今後、自動テストを追加する場合に価値の高い境界は次のとおりです。

1. 有効、無効、省略、CIDR、ドット区切りマスクの解析と検証
2. 通常のプレフィックスと境界プレフィックスにおけるサブネット情報の正確性
3. すべての移動経路における`ipAddrString`と`ipBlock`の同期
4. 特殊用途アドレスの双方向の包含判定
5. SVGの詳細をテストする前段階としての純粋なツリーデータ生成
6. クリックによる選択と再描画の結合動作

テスト可能な関数を抽出する前に、現在の計算ロジックがVueコンポーネントのメソッドとcomputedプロパティ内にあることに注意してください。解析、書式変換、特殊用途範囲の照合、ツリー生成を小さな純粋関数のモジュールへ分離すれば、すべてのケースでUI全体をマウントせずに安定したテスト境界を作れます。

## 10. アーキテクチャ上の制約とリスク

- **IPv4専用の前提:** 正規表現、32ビット変換、静的データ、ツリー構築のすべてがIPv4を前提としています。
- **結合されたストアフィールド:** 変更経路が一方だけを更新すると、アドレス文字列と`Netmask`オブジェクトが不整合になる可能性があります。
- **シリアライズできない状態:** `Netmask`インスタンスは、永続化やデバッグツールの利用を複雑にします。
- **命令的な描画:** D3による更新はVueのライフサイクル変更と整合させ、古いDOMノードやwatcherが蓄積しないようにする必要があります。
- **静的なレジストリデータ:** 特殊用途アドレスとRFCのメタデータは手動保守が必要で、最新のレジストリを反映していない可能性があります。
- **古いツールチェーン:** Vue CLI 4とベータ版のElement Plusが依存関係の更新を制約しているため、移行は慎重に行う必要があります。
- **回帰テストがない:** 計算やUIの変更には、lint/buildチェックに加えて手動検証が必要です。

## 11. 推奨する改善順序

今後の保守では、次の順序で進めるとリスクを抑えられます。

1. 現在の振る舞いを変更せず、対象を絞ったテストを追加する。
2. 入力解析と書式変換を純粋関数として抽出する。
3. 特殊用途範囲の照合とツリーデータ生成を純粋関数として抽出する。
4. 2つに分かれたmutationを、選択状態をまとめて更新する1つのmutationに置き換えることを検討する。
5. 計算と操作のテストが整ってから、Vue CLIとElement Plusを更新する。

これらは推奨事項であり、現在の機能を説明するものではありません。依頼範囲として明示されない限り、1つのタスクですべてを実施しないでください。
